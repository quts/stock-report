# Stock Report — Phase 0 Feasibility & POC Plan

> 狀態：Phase 0 POC 已執行；當前驗收結果與正式 GO／NO-GO 依 [Phase 0 Review](phase-0/phase-0-review.md)，本計畫不是授權或測試證明。
> 依據：[Product Specification V0.2](./product-spec-v0.2.md)  
> 目的：在投入正式系統開發前，驗證「免費資料來源＋僅供本人使用的 PDF＋本機 Mac Codex 訂閱」是否足以支撐可信研究，並形成 Go / Conditional Go / No-Go 結論。  
> **2026-11-15 範圍變更（使用者明示）**：輸出僅供使用者本人使用，永不分享；原「分享版 PDF／再散布授權」驗證項目已改為「個人 PDF／內部使用授權」。個人使用不等於已取得權限，unknown／restricted 來源仍封鎖。

## 1. 邊界、前提與成功定義

- 資料 API **US$0/月**；不能未經同意採購資料、啟用付費 API 或使用僅標榜免費試用的付費權限。
- 使用者以本機 macOS + 現有 Codex/ChatGPT 訂閱為優先。獨立 LLM API **不是** POC 必要前提，亦不得自動扣款。
- 研究涵蓋 US equities、TWSE 與 TPEx；股票入口和事件入口；事件最多五家公司。
- 輸出研究期間 **3–6 個月**、**6–12 個月**的獨立方向性提案；只要有足夠合法證據，財務／估值或投顧資料部分缺失可降級產 PDF。
- POC 驗證的是**資料可得性、證據流程、Policy Gate、Codex 互通與 PDF**，不是 3–12 個月預測是否有效。
- **任何結果必須明示 Real Data 或 Mock Dataset**，測試成功不得掩蓋真實資料未取得、授權未確認或研究失敗。

## 2. 四個測試標的與兩個研究入口

| 案例 | 代碼 | 目的 |
| --- | --- | --- |
| 美國大型科技 | NVDA | 美股官方申報、行情、新聞與機構評等 |
| 美國半導體 | AMD | 同業比較、財務計算、事件關聯 |
| 台灣上市 | 2330.TW | 台灣上市交易所資料、財報、代碼識別與評等 |
| 台灣上櫃 | 6488.TWO | TPEx 取得能力、不同交易市場／代碼與授權 |

**股票 E2E**：至少 NVDA 與 2330.TW 各一個研究案例。  
**事件 E2E**：選一項可以由公開官方資料確認的跨台美股產業／政策事件；列出候選股票與直接、間接、假設關聯，選最多五家深入分析。若找不到符合條件的真實事件，應記錄 blocker；不可捏造。

每個案例需指定研究截止時間（含時區）、資料採樣期間與當時已公開的資料期別。採 Real Data 的 POC 必須記錄實測日期與 API 回應，而非僅引用 API 文件。

## 3. Data Provider Feasibility Matrix

對每個候選來源（**候選不代表已確定可用**）填入下表：

| 資料領域 | 免費候選來源 | 必須核對 |
| --- | --- | --- |
| 美國官方申報 | SEC EDGAR / XBRL、公司 Investor Relations | 申報資料、時間序列、使用限制與調用政策 |
| 美國歷史行情 | 可公開使用的交易所、官方資料或其他免費 Provider | 日資料可得性、調整價格、額度、內部使用授權 |
| 台灣上市行情與公司資料 | TWSE OpenAPI、官方公開資訊 | 開放資料集與商業行情授權的差別，歷史深度、使用條件 |
| 台灣上櫃行情與公司資料 | TPEx 官方資料／OpenAPI | 歷史深度、可得範圍、內部使用條款 |
| 台灣公司財報／公告 | 公開資訊申報來源、政府開放資料 | 檢索方式、公告時間、資料集授權 |
| 全球新聞事件 | GDELT、官方新聞稿、允許使用的 RSS | 原始內容非必然可保存或使用；保存標題/摘要/連結的範圍 |
| 公開投顧評等 | 有來源的可公開評等公告或新聞紀錄 | 逐機構識別、當前有效性、去重、資料涵蓋、內部使用權 |

**不得以第三方網站可讀/可爬取、或報告只供個人使用，推斷已取得使用權。** 對每一來源記錄官方條款 URL、查證日期、是否允許內部研究（個人 PDF 的權限依據）、是否允許本機留存原始回應／雜湊、引用要求、速率限制、是否要 API Key、實際測試證據。條款不清楚時不得把其數據／圖表放入個人 PDF、指標或提案，標為 `LICENSE_UNKNOWN`。再散布權不在驗證範圍：報告不對外分享，個人報告不需要再散布簽認。

### 每個標的的資料覆蓋清單

驗證下列項目是否有資料、正確期別、來源、授權、缺失原因：

1. Ticker、交易所、公司法定名稱、幣別及股類。
2. 最近有效收盤價、歷史日行情及成交量。
3. 可用的最新已公開財報、營收、獲利和現金流。
4. 重大公告／新聞事件（事件日、發布日、擷取日）。
5. 逐機構評等（機構、原始評等、發布日、目標價、原文來源）。
6. 已知關聯公司、直接/間接/假設連結與依據。
7. 是否已確認可內部使用於個人 PDF、需要哪些引用；本機原始稽核留存是否另獲允許。

輸出 `data-coverage.json`，統計 **可得／部分可得／不可得／授權未知**；不得虛構覆蓋比例母數。

## 4. Codex / LLM Provider POC

目的是證明訂閱優先架構可用，而非承諾 Codex 訂閱提供永久、自動化、無限額度的 LLM API。

### 4.1 互動模式（MVP 必驗）

在本機 Codex 工作區以自然語言觸發固定 Python 程式：
1. Python `prepare` 生成確定性、Schema 驗證的 `research_input.json`；
2. Codex 只依提供的證據產生 `ai_proposal.json`，包含各期限展望、來源 ID、支持/反證與假設；
3. Python `finalize` 驗證 Schema、Gate、產生可取得的 PDF 與 manifest；
4. 回覆研究範圍、路徑、資料缺失與執行結果。

至少 **10 個固定情境**（包含正常、矛盾證據、缺財務／估值、缺全部評等、未核實事件、錯誤來源 ID）測試。合格標準：全部有效結束為符合 Schema 的提案，或可觀測且正確的拒絕/錯誤；不得默默生成成功假象。保存失敗類型、訂閱額度/登入限制（若可查）、執行耗時及是否需要人工介入。

### 4.2 非互動/訂閱登入可行性（探索性）

可探索 `codex exec` 或同等官方支援途徑，但須實測目前安裝的 CLI、登入狀態、可輸出 Schema 的能力和執行權限。無法可靠支援時，不妨礙互動模式 POC 通過；不得偷換成付費 API。

### 4.3 LLM 安全與成本

外部新聞與公告文本不可信，不可讓其執行權限、呼叫工具或修改 Repository。預設只處理標準化輸入、寫入受控位置。記錄每次分析模型／Prompt 版本、token/用量（若可取得）、耗時與重試；不得暴露 token、登入憑證或私密資料。

## 5. Policy Gate 故障注入（必驗）

| 注入情境 | 預期行為 |
| --- | --- |
| 不存在的官方公告／虛構重大事件 | 不能作為已核實事實或支持正式結論 |
| AI 引用不存在的 Evidence ID | Hard Reject 相關結論 |
| 提供 `research_as_of` 之後才公布的資料 | 排除 future data；對應推論不得通過 |
| Quant 值與公式／原始數字不一致 | 拒絕錯誤數字、重新計算或降級 |
| 投顧評等為空 | **仍生成 PDF**，顯示「投顧共識資料不足」 |
| 財務或估值部分缺失 | 省略缺項；若其餘證據充分，可發布附限制展望 |
| 核心證據不足 | 對應期限輸出 `insufficient`，不可默認 `neutral` |
| Quant 與 AI 方向相反 | 保留分歧與原因，不直接平均為 Neutral |
| 同一機構重複報導／重複評等 | 去重，不能按文章數計算機構數 |
| 未確認內部使用權限（unknown／restricted）的資料 | 不得輸出受限制的內容，亦不得支撐指標或結論 |
| 內部使用已確認、再散布欄位為 false 的資料 | **可**用於個人 PDF、指標與提案；再散布欄位不是 Gate |
| 事件僅為猜測且關聯不明 | 標 Hypothetical 或不列入深入研究名單 |

Gate 回傳 `APPROVED`、`APPROVED_WITH_WARNINGS`、`REVISE`、`REJECTED`，記錄規則 ID、證據 ID 與受影響的研究期限。不得以 Gate 通過聲稱投資研究方向正確。

## 6. 測試分層與可重現性

### A. Deterministic Unit / Contract Tests

使用固定測資驗證：Ticker／交易所、幣別與時區、價格與財務公式、機構級去重、評等映射、報告 JSON Schema、授權狀態判斷。所有規則化測試必須全數通過。

### B. Mock End-to-End Tests

使用可追溯的合成 Golden Dataset 測試：
- 股票研究（US、TWSE、TPEx）。
- 事件研究（含直接、間接、Hypothetical 的關聯）。
- 3–6 與 6–12 個月兩套判斷，允許不同方向或 Insufficient。
- 缺評等仍成功產生標示不足的 PDF。
- Policy Gate 的故障注入情境全部符合預期。
- 自然語言 → Request → Prepare → Analyze → Finalize → PDF。

Mock 報告必須明確有 **DEMO / SYNTHETIC DATA** 標記，不可當成真實研究；與所有報告相同，僅供個人使用、不得散布。

### C. Real Data Smoke Tests

以真實的官方來源及授權允許的資料測 NVDA 與 2330.TW，盡可能納入 AMD、6488.TWO 與跨市場事件。每個測試必須列出實際取得值、時間、來源、失敗原因、授權證據與對報告的影響；若僅能產 Partial Report，就誠實標示。

### D. Replay / Version Tests

同 `research_input` 快照、`ai_proposal`、Policy 版本、模板，重播必須產生相同數值、相同方向及 Gate 結果；重新抓資料或重新呼叫 LLM（Fresh Run）不保證逐字相同。PDF 需比較內容與渲染品質，不要求第一版二進位 Hash 相同。

## 7. PDF POC 驗收

需產出**股票研究與事件研究各一份** 1–2 頁 A4 繁體中文 PDF（Mock 可以驗證版型，Real Data 作為授權與真實資料 Smoke Test）。

- 3–6、6–12 個月展望分列，有正反證據、反轉條件、對應資料期間。
- 投顧資訊不足要保留明顯「資料不足」標記；禁止以假造評等填補。
- 中文字體正常、無溢位、截斷、錯頁、過小字體。
- 核心數字與引用必須對應研究 JSON，PDF 不得出現未經 Gate 審核的關鍵結論。
- Event Report 深入公司數量 `<= 5`，並清楚標記直接／間接／假設。
- 所有進入 PDF 的內容應經 License Policy 的內部使用檢查；保留研究與數據截至時間、使用限制與簡要引用。
- 每頁標示「僅供個人使用・不得散布 / Personal use only / Not for distribution」。
- 完整機構明細與來源清單保存 JSON，避免擠壓兩頁主報告。

## 8. Go / Conditional Go / No-Go

### GO（開始正式 MVP 實作）

以下條件需**全部**成立：
1. 四種股票代碼/市場均能正確辨識；台美股至少各一個案例可合法取得核心真實研究資料。
2. 沒有以無授權或未確認內部使用條款的資料進入個人 PDF；每個 Provider 有可追溯的授權紀錄。
3. Python 確定性測試及 Policy Gate 必驗案例全部通過。
4. Codex 本機互動模式能在受控條件下產出合法結構化提案或正確報錯，不額外依賴付費 API。
5. Mock 的股票、事件雙入口 E2E 與兩種 PDF 模板驗收通過。
6. 至少有台股和美股的 Real Data Smoke Test，清楚標示覆蓋、限制與是否能產出真實資料的個人報告。
7. 重播時統計、Gate 與研究方向一致；所有關鍵事實可追溯或明確標示假設。

### CONDITIONAL GO（縮減或分段實作）

部分非核心資料（例如投顧評等、某些估值／歷史行情）不足，但仍有合法可靠的核心資料可生成**標示限制**的研究 PDF；提出精確的功能限制、需先解決的 blocker、替代 Provider 與再次驗證條件。不得為趕進度放寬授權或重大事件查證。

### NO-GO（暫停正式實作或該市場功能）

- 無法確認關鍵真實資料可內部使用於個人 PDF。
- 核心資料反覆錯誤、公司識別或時點不可靠，導致正式研究不可用。
- Hard Gate 注入案例失敗，虛構引用／未來資料／未確認重大指控仍可進入正式研究結論。
- 只能使用 Mock 流程產出漂亮 PDF，無真實來源可驗證。
- 本機 Codex 不能完成受控結構化分析，且沒有經核准的零額外費用備援方案。

Go/No-Go 應按**市場與能力**細分：例如 US Stock Research GO、TWSE Conditional GO、評等統計 Partial，不必因個別免費 Provider 不可得就宣布所有功能失敗。

## 9. Phase 0 交付清單

請用單一 POC Review Bundle 呈交：

1. `provider-feasibility.md`：候選來源、測試日期、端點、覆蓋、速率限制、原始條款／內部使用授權及判斷。
2. `data-coverage.json`：四標的 x 欄位的可得性、缺失與授權狀態。
3. `llm-evaluation.json`：本機 Codex 受控結構化分析 10 例及執行限制。
4. `policy-gate-tests/`：Golden Dataset、故障注入案例、預期/實際結果。
5. `sample-stock.pdf`、`sample-event.pdf`：明確區分 Mock 與 Real；若無法生成真實資料 PDF，要記錄 blocker。
6. `research-manifest.json`：資料／Prompt／模型／Gate／模板版本及 Replay 記錄。
7. `phase-0-review.md`：按市場與能力分別提出 GO / CONDITIONAL GO / NO-GO，列出不足與下一步。

## 10. 排除事項與執行紀律

Phase 0 **不**實作交易下單、不做公開上線、不做任何分享／散布功能、不購買 API、不保證有全市場分析師覆蓋、不聲稱預測績效、不建立後台排程服務或大型 Agent 框架。POC 的程式只為驗證資料、權限、介面與報告能力；若需要擴大 MVP，先經 Review。

本文件記錄 Phase 0 的驗收要求，不是資料授權取得的證明。POC 已執行，實際結果與未通過條件由 Phase 0 Review 及 reports/phase-0/acceptance.json 分別記錄；離線驗收不等於正式 MVP GO。
